# ПБ Консультант: подготовка к поиску и план продвижения

Основной адрес: **https://консультант.site/**. Окончание `.site` — латиницей.
Техническая запись того же домена: `https://xn--80atdhccwjcf4h.site/`.
Домен `консультант.сайт` — другой адрес.

## Что проверено 4 ноября 2026 года

- Главная основного домена открывается по HTTPS и возвращает HTTP 200.
- HTTP-версия пока тоже возвращает 200, без перехода на HTTPS.
- Старый адрес `the-final.vlad-volkov08.workers.dev` показывает тот же сайт.
- На опубликованном сайте отсутствуют canonical-адреса страниц; `/sitemap.xml` возвращает 404.
- Опубликованный `/robots.txt` доступен, но не содержит ссылки на Sitemap. Запрета индексации главной в проверенном HTML и заголовках ответа нет.
- Проверка обычным автоматизированным клиентом с User-Agent `Python-urllib` получила 403 / Cloudflare 1010. С User-Agent `PB-Site-Availability-Check/1.0` те же запросы проходят. Это не проверка настоящих роботов Google или Яндекса: их доступ нужно проверить средствами поисковых кабинетов, а при ошибке — по событиям Cloudflare.
- Все 10 адресов будущей карты сайта проверены с `PB-Site-Availability-Check/1.0`: возвращают HTTP 200 на конечном HTTPS-адресе.
- Состояние индексации, показы и позиции пока не подтверждены: доступа к данным Яндекс Вебмастера и Google Search Console в этой проверке не было.

## Что подготовлено в этой ветке

- Основной HTTPS-адрес для каждой из 17 содержательных страниц, включая страницы услуг и дела. Учтены реальные переходы Cloudflare: `/index.html` → `/`, `/uslugi/index.html` → `/uslugi/`, остальные `.html` → адрес без расширения.
- Название бюро в начале заголовка главной, описания служебных страниц и согласованные метаданные для ссылок.
- Машиночитаемые сведения о сайте и бюро: название, публичные телефон и почта. Физический адрес, реквизиты, отзывы и рейтинги не добавлялись.
- `robots.txt` со ссылкой на карту сайта.
- `sitemap.xml` с 10 готовыми страницами: главная, каталог практик, семь подробных практик и опубликованное дело.

Пять практик с плашкой «Подробное описание готовится» сохраняют рабочие ссылки и не закрыты от индексации. Пока они не включены в Sitemap; после утверждения подробного описания нужно убрать плашку и обновить карту. Юридические документы доступны по ссылкам, но в карту для продвижения не включены. Страница ошибки сохраняет `noindex` и не включена в карту.

Эти изменения появятся на сайте только после слияния PR и успешной публикации Cloudflare. Подготовка файлов сама по себе не означает, что поисковики уже включили страницы в поиск.

## После публикации

1. Проверить HTTP 200 и содержимое `/robots.txt` и `/sitemap.xml` на основном домене. Убедиться, что карта указывает основной домен и конечные адреса страниц, а не старый Workers-адрес.
2. В Cloudflare для домена открыть **SSL/TLS → Edge Certificates → Always Use HTTPS** и включить автоматический переход на HTTPS. После этого проверить, что HTTP ведёт на HTTPS без цикла. Настройки аккаунта меняет владелец.
3. Добавить `https://xn--80atdhccwjcf4h.site/` в [Яндекс Вебмастер](https://webmaster.yandex.ru/) и подтвердить права способом, который предложит сервис. Код подтверждения берётся из своего кабинета.
4. В [Google Search Console](https://search.google.com/search-console/) добавить доменный ресурс `xn--80atdhccwjcf4h.site` и подтвердить его DNS-записью из кабинета. Альтернатива — ресурс с префиксом URL `https://xn--80atdhccwjcf4h.site/` и один из предложенных способов подтверждения.
5. В обоих кабинетах отправить `https://xn--80atdhccwjcf4h.site/sitemap.xml`. Проверить главную, каталог и страницы приоритетных услуг инструментами проверки URL. При успешной проверке запросить индексирование / переобход.
6. Если поисковый кабинет показывает 403, проверку робота или недоступные ресурсы, найти соответствующее событие Cloudflare. Исправлять конкретное правило; общий доступ проверять повторно через поисковый кабинет.
7. Проверить выбранный поисковиками основной адрес: он должен вести на домен бюро. Перенаправление старого Workers-домена на основной — отдельная настройка, в этой ветке оно не добавлено.

## Содержание для привлечения обращений

Начальный приоритет — согласовать географию и 2–3 услуги, по которым компания действительно хочет получать новые обращения. Все заявленные на сайте города сохраняются; место нахождения офиса и приоритетный регион не придумываются.

Возможные группы запросов для изучения спроса, а не готовый прогноз трафика:

| Направление | Как клиент может искать помощь | Что должно быть на странице |
| --- | --- | --- |
| Таможенные споры | Оспаривание таможенной стоимости; обжалование решения таможни | Типичные ситуации, порядок работы, возможные результаты, подтверждённый кейс |
| Налоговые споры | Обжалование решения налоговой; юрист по налоговым спорам | Стадии спора, задачи бюро, порядок первого обращения |
| Интеллектуальная собственность | Защита товарного знака; спор об исключительном праве | Какие права и ситуации рассматриваются, ход работы, примеры из практики |

Следующие материалы готовятся совместно с юристами: подробные описания пяти оставшихся направлений, обезличенные реальные кейсы, подтверждённый опыт команды и ответы на частые вопросы клиентов. Правовые утверждения и результаты дел проходят проверку специалистом компании до публикации.

Для каждого материала нужен понятный путь к обращению: ссылка на подходящую практику, форма или контакт партнёра. Дополнительные страницы по городам создаются только при наличии содержательных местных различий и реальной услуги. Не нужны десятки одинаковых текстов с заменой названия города.

Карточки организации и внешние справочники можно оформить после согласования публичных реквизитов, адреса/формата работы и региона. Отзывы — только от реальных клиентов с их разрешения.

## Как оценивать результат

Первый контроль: поисковые кабинеты подтверждают доступ к страницам, обработку карты сайта и появление готовых страниц в индексе. Затем еженедельно фиксировать показы, запросы, переходы и реальные обращения из поиска. Аналитику отправок формы подключать отдельным согласованным изменением; на этом этапе её счётчик не установлен.

Позиции и обращения не возникают сразу после добавления Sitemap. Сначала проверяем обнаружение и индексирование страниц, затем оцениваем спрос и улучшаем материалы по фактическим данным.

## Обновление файлов разработчиком

После добавления страницы или утверждения описания:

```text
node tools/update-search-metadata.cjs
node tools/update-search-metadata.cjs --check
node tools/check-navigation.cjs
```

Генератор обновляет canonical, метаданные, JSON-LD, robots и Sitemap; существующее содержимое страниц сохраняет. Он не создаёт коды подтверждения, не отправляет сайт в поисковики и не меняет настройки Cloudflare.

Официальные источники: [руководство Google по SEO](https://developers.google.com/search/docs/fundamentals/seo-starter-guide), [основные адреса страниц](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [индексирование в Яндексе](https://yandex.ru/support/webmaster/ru/robot-workings/robot.html), [карта сайта в Яндекс Вебмастере](https://www.yandex.ru/support/webmaster/ru/indexing-options/sitemap), [Always Use HTTPS в Cloudflare](https://developers.cloudflare.com/ssl/edge-certificates/additional-options/always-use-https/).
